# Personal OS｜云端备份与恢复交互草案

## 2026-11-08 实施状态

导出和本地校验已实现：未加密范围勾选 → 接收完整包 → Worker 校验 → 用户显式保存文件；可取消/清除、失败重试、退出清除暂存链接。尚未实现恢复预检与写入；下方第 4/5 节的恢复流程仍是后续方案。真机文件保存待联验，具体边界见[实施交接](../02-engineering/cloud-backup-export-implementation.md)。

用途：定义设置中的主动导出、文件校验、恢复预检及确认流程；对应 F11/A17 和 BKP-01～06。
日期：2026-11-08（Asia/Shanghai）。状态：方案待 Owner 确认；没有新增页面、按钮或截图。数据和技术边界以[工程方案](../02-engineering/cloud-backup-restore-v0.1.md)为准。

## 1. 入口与术语

仍为五模块导航。设置承载“云端档案备份”，其下分别为导出、校验、从文件恢复；旧版浏览器 JSON 导出维持独立，不能给旧包套用新的云端格式。回收站已有“恢复”仅撤销移入；“从备份恢复”是独立操作，不合并按钮或暗中转换。

不新增第六模块、公开下载主页、AI 整理或自动备份通知。手机以单列和可展开清单展示，避免桌面大表格横向滚动。

## 2. 完整导出

设置 → 显示全量范围、回收站及 inactive Focus 纳入说明、未加密/私密文件提示 → 点击“导出完整云端备份” → 本人验证/只读快照 → 原件读取和校验 → 浏览器下载。

- 不继承全局领域/搜索/复盘周期筛选，预览真实对象与原件数量，不使用演示数值。不是导出量评分。
- 生成中显示实际阶段；没有可计算总进度时只显示“正在准备/读取原件”，不编造百分比。防重复点击不代替服务端控制。
- 初次空档案也可生成格式有效的零内容包，说明没有记录；不能与读取失败混为一谈。
- 某原件缺失/哈希错误/超限时明确“完整备份未生成”；不静默略过或说文字已备份。传输中断可能已有不完整下载，提示不要用于恢复。
- 页面只报告可观测阶段，不凭 HTTP 成功宣称手机已把文件保存到指定目录。提供“校验已有备份”入口来验证用户实际选中的文件。
- 可取消生成/传输；取消不删除或修改云端内容。不承诺关闭页面后后台继续、自动落盘或跨刷新续传，除非对应能力确已实现并验证。

## 3. 文件完整性校验

选择本机 ZIP → 本地读取/校验（此阶段不上传） → 显示格式、快照时间、正常/回收站记录和各类 entry/原件计数 → 显示完整、损坏、不支持或超限。

“包完整性通过”不等于“目标空间可恢复”，也不等于有完整平台灾备。哈希不符或缺原件时，不提供继续写入按钮。旧版 JSON 单独说明格式不匹配，不伪装升级成功。

## 4. 从备份恢复

本地校验通过 → 用户选择进行目标预检并明确同意必要元数据提交到自己的服务 → 本人服务器只读比对 → 展示新增/相同跳过/冲突/不支持清单 → Owner 确认 → 接收原件 → 数据库批次提交 → 结果核对与读回。

预检摘要必须区分：

- 将新增的正常记录、回收站记录、方向、Focus（包含 active 状态）、周/月复盘和原件数量。
- 哪些完全相同将跳过；哪些同 ID 有内容或回收站状态差异使整批停止。
- 所有不支持关系/缺件/容量问题；有问题时只能取消或重新选择有效备份，不提供强制覆盖。

确认文字应明确“补入这些缺失内容，不覆盖或清空现有档案”。新增 Focus/Direction 必须在预览范围内，不能以恢复为名静默调整已有目标。首版不提供部分勾选导入，以免漏掉被引用对象；如需选择性导入须另设计关系闭包和确认。

## 5. 错误、取消与返回

| 阶段                  | 反馈与返回                                               | 写入边界                                     |
| --------------------- | -------------------------------------------------------- | -------------------------------------------- |
| 未登录/会话过期       | 解释需本人登录，回到设置；不可为完成任务切换成公开 URL   | 不擅自发送登录邮件；恢复写入前再校验会话     |
| 本地格式/哈希检查失败 | 显示缺件/版本/损坏原因，重新选文件或取消                 | 不向云端发送原件、不写记录                   |
| 只读目标预检冲突      | 展示差异类别，可展开脱敏摘要；取消不改变目标             | 零恢复写入；差异不得写入开发日志             |
| 原件接收失败/中途取消 | 明确逻辑档案尚未恢复，可能保留私有暂存；支持当前批次重试 | 不覆盖原件、不自动删除暂存                   |
| 提交冲突              | 提示目标已变化，重新预检；不能把客户端旧预览当最终决定   | DB 逻辑事务回滚，暂存可能仍在                |
| 提交结果未知/断网     | 显示“正在核对本次结果”，按批次查询；不让用户重复新建批次 | 不猜测事务已回滚，不以取消按钮删除已提交数据 |
| 成功                  | 分别列出新增/跳过/保留回收站计数；提供返回对应模块核对   | 不宣称已有记录被回滚到备份时点               |

关闭尚未确认的预览可返回设置并保留原有筛选；仅会话内临时状态，不默认承诺刷新后保留文件句柄。实际接收/提交阶段离开要说明后台状态和核对入口，具体跨刷新能力依持久批次实现与验证而定。

## 6. 可访问性与设备验收

桌面 1440、手机 390、窄屏 320、平板 768：检查单列/卡片、无横向溢出、长文件名换行、触摸区至少 44px。重点验证 Safari/iOS 实际文件保存和文件选择，不只用 Chromium 的移动视口代替真机结论。

键盘操作可完成文件选择、展开冲突、取消和确认；弹层焦点受控，关闭返回触发按钮；进度/错误使用可读状态消息。不能用仅颜色、自动消失的提示或模拟下载帧作为成功证据。
