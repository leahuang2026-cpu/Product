# Personal OS｜核心流程技术可行性（T01）

> 用途：分析持久化、失败处理、移动端和权限，给出最小实现与验证办法。
> 状态：方案评估，不是云端功能已实现或测试通过的报告。
> 更新：2026-11-06（Asia/Shanghai）。
> 对照：上传 PRD V1.0 F01–F11、A01–A18 与 [T01 基线](../00-product/t01-product-baseline.md)。

## 总体判断

四条流程都可用现有 Web 技术实现。主要工作量不在页面展示，而在用户身份、原件与数据库的一致性、重试幂等、跨设备写入冲突以及 AI 范围控制。没有需要先研发新算法的阻碍，但关键产品语义未定时不能冻结模型或验收。

| 流程     | 可行性与相对难点                                           | 当前可复用                           | 主要缺口                                                 |
| -------- | ---------------------------------------------------------- | ------------------------------------ | -------------------------------------------------------- |
| 文字记录 | 常规 CRUD；原文编辑语义、中文搜索、冲突处理需设计          | 表单、原文校验、列表、检索、错误提示 | 云存储、保存后分类、用户编辑、加载失败与权限             |
| 图片记录 | 常规私有存储；跨服务一致性和原图鉴权较难                   | 文件选择、详情展示、合成图片 E2E     | 原件对象存储、上传状态/重试、鉴权读取和移动编码          |
| Focus    | 轻量关联与单下一步可行，主要风险是产品语义                 | Goal/Project 创建、卡片、响应式首页  | 独立选择/引用关系、编辑/移出、云同步                     |
| AI 处理  | 可做明确材料清单网关；外发边界、成本和引用可靠性需专门验收 | 独立结果区域、确认交互模式           | 实际模型、请求权限、输入快照、取消与结果保存；本轮不实现 |

不估算无依据的精确工期、吞吐量、费用或成功率。相对难度只是工程判断，非已测性能。

## 文字：输入 → 保存 → 分类 → 查看 → 编辑 → 搜索

1. 表单接收纯文字，允许中文与换行；服务端校验空白、长度和会话。客户端生成一次提交的幂等键，写入成功才显示已保存。用户修改内容后重试应成为新提交，不能错误复用旧 payload 的键。
2. 先创建记录，再显示分类；分类是独立写入，失败不能回滚或隐藏已成功的原文。PRD 的五领域单选、未分类/跳过是拟定设计，须确认后实现；字段选择不依赖当前原型必填 domain。
3. 详情按 owner 查询。明确区分无权限、无记录、网络错误与空列表。授权过期时保留当前未提交输入并提示重新登录，不把未保存内容误报同步成功。
4. 编辑需区分说明、分类与原始正文。F03 的补说明与改分类可作为首批候选；完整原文编辑及版本历史待 D15。若获批，追加用户 revision，通过 expectedVersion 乐观锁更新当前显示；拒绝冲突，显示两版本让用户决定，不自动合并/覆盖原始输入。
5. 搜索优先正文与用户图片说明（F03/A06），不声称能搜索未做 OCR 的图中文字。中文以参数化基础匹配评估，分页、RLS 与可能的 trigram 索引在专用环境验证。旧版本是否进入搜索待确认。

**移动端**：软键盘遮挡、中文输入法组合态、误触提交、页面切后台或意外关闭可能丢失尚未保存输入。先在失败但页面仍打开时保留表单；跨刷新离线草稿不是默认承诺，若需要则选择 IndexedDB 草稿并明确共享设备风险。

**验证建议**：A01、A03–A06、A10/A11；加重复请求、断网、认证过期、中文与长文本、两个设备并发编辑。原有本地 E2E 不能验证云端权限和同步。

## 图片：上传 → 保存原图 → 查看 → 分类

建议流程：创建 owner 约束的 pending record/attachment 与上传意图 → 客户端直传唯一私有对象键 → 服务端核验对象存在、所有权、大小/内容类型 → 将附件及图片记录原子标为 ready → 展示保存成功并进入分类。

- 数据库和 Storage 不支持同一跨服务事务。上传完成但 finalize 失败时，用相同操作 ID 重试完成；上传失败保留文件选择/页面状态，不能创建重复可见记录。后台孤儿清理只处理技术 pending 对象，清理期限与策略需评审，不能借此删用户 ready 原件。
- 原图字节不可被缩放、压缩或 OCR 输出替换；预览/缩略图是可再生成派生文件。对象键不可覆盖，文件哈希用于校验与恢复，不默认按哈希全库去重（会引入归属和删除语义）。
- 检查扩展名、MIME 和实际文件头；不信任浏览器声明。单张 JPEG/PNG 是 PRD 拟定最小格式，不把原型 WebP/1 MB 直接定为需求。HEIC、EXIF 方向、大图解码内存及定位元数据需用脱敏手机样本评估。若不支持则明确提示，不静默丢原件。
- **A10 权限**：读取图片的应用地址每次验证会话及 owner，然后流式取私有原图；不发公开地址或可转发的签名读 URL 作为默认原件入口。页面、API、搜索结果、缩略图都使用同一隔离规则。用户已合法下载的字节不能被技术“撤回”，不承诺这种能力。
- 大文件上传避免经过 Vercel 函数请求体；直传和鉴权流式读取仍有流量/函数限制，最大文件与超时需核实套餐。上传 URL 要短时、限单对象，不赋予列举或读取权限。

**移动端**：相册/相机权限、网络切换、后台中断、重复点保存、图片长宽比与解码失败必须测试。浏览器原生文件选择优先；断点续传在实际大小需求明确后评估，不预置复杂队列。

**验证建议**：A02/A03/A04/A10/A11；使用真实编码但非私人内容的样例，核对存储原件哈希；模拟对象成功/元数据失败及反向失败；复制图片地址到未授权上下文验证拒绝。

## Focus：重点 → 关联 → 一条下一步 → 首页

建议独立 Focus 数据或轻量引用集合，不用 `projects.slice(0, 2)` 代表用户意愿。可复用现有 Goal/Project 作为选择项；下一步按 PRD F05 的简短文本候选，不引入日期、任务完成率、通知或完整任务系统。

保存重点标题、关联对象及下一步为同一事务；关联 FK 和 owner 必须一起检查。首页查询当前选定项及关联名称，直接改方向名称后应读到新名称，不维护相互失步的复制字段。移出关注的候选操作只改变当前显示，不删除项目、方向或历史记录。

关联单个/多个、是否可为空、关注数量/排序/“移出”的规则都是 PRD 拟定/待评审项。状态未定时不写死 active 上限。若引用项目与方向发生矛盾、关联被移除或名称变更，展示事实并请求用户处理，不自动替换成“推荐”目标。

**验证建议**：A08/A09/A11；跨设备创建/编辑下一步/移出；无关注、未补全、关联无权限、并发修改和窄屏显示。既有 Action 勾选功能保留在原型中，不因此扩展新版 MVP。

## AI：明确选择 → 主动请求 → 预览结果 → 决定保存

仅评估。F08/F10 未批准时不安装模型 SDK、配置真实密钥或发出请求。

候选实现：请求体带本次选择的 record IDs、revision IDs、attachment IDs、操作类型；服务器验证每项属于当前用户并固定版本快照，展示实际材料清单及处理范围。把“所选记录”不明示的其他附件、其所有关联、先前对话和全库检索排除；选择粒度/必要上下文需 Owner 明确。

服务端模型适配器只取得已校验材料，模型返回不可信文本：不把附件中的指令当执行授权，不赋予修改目标/删除/发布工具。渲染结果防脚本注入；事实引用映射到选定来源，不能靠模型自报 ID 验证来源。OCR 无文字、模型不确定或来源缺失时显示真实状态，不造经历。

结果先以未保存预览呈现，用户点击保存才写独立派生结果和引用。取消不写入业务档案；提供商已收到的材料和其留存不可撤回，须事先确认政策。超时/重试要控制重复费用，用户取消也不保证远端已停；对可追踪请求做幂等和状态区分，不无限重试。

**验证建议**：A13/A16/A18 的条件验收；加入未选对照记录、未选附件、跨账号 ID、提示注入、处理后编辑原文、流式中断和不保存离开页面。每项都要验证实际向模型发送的脱敏请求集合，不能只查看 UI 选择状态。

## 后续输入与待验证边界

语音/链接在文字图片之后。语音原件保存与主动转写是两次操作，失败不丢音频；不同手机编码与可选转写服务成本需测试。链接先存 URL/说明，全文读取和摘要独立批准；若以后读取外站，需要 SSRF、重定向、内网地址与认证内容保护，但本轮不建设抓取服务。

浏览器兼容、云权限、RLS、对象一致性、跨设备冲突和备份恢复尚无实际实现证据。架构可行与验收通过是两回事，详见 [工程审查](engineering-audit.md)。
