# Personal OS｜BKP-04 恢复前只读预检

用途：说明本轮只读对比的发送范围、判断规则、权限与验收边界。
日期：2026-11-08（Asia/Shanghai）。状态：Owner 在只读预检建议后明确回复“推进”；代码及本地测试完成，Render 更新待核查；恢复写入 BKP-05/06 未授权实施。本轮不新增 SQL、表、Storage 权限或环境变量。

## 1. 已确认范围与复用

复用已安装的 `personal_os_backup_snapshot_v1()`、本人会话/RLS、现有 ZIP 完整性校验；不重复安装数据库。先在本地完整校验原件与 JSON，然后由用户明确同意并发起 `POST /api/backups/restore/preview`。输入为 formatVersion=1 与结构化 snapshot，不上传 ZIP 或原件字节。

新增 `validateBackupDetails` 保留已校验快照，旧 `validateBackup` 摘要接口保持兼容。Worker 在全包通过后才返回 summary/snapshot；换文件、生成新包或清除会销毁旧预检组件，退出登录/离开设置同样取消请求并清空临时结果。未勾选并主动点击不会调用预检接口。

## 2. 发送内容与权限

界面说明并允许展开：本次已校验包的原文、条目正文、说明、领域、灵感标记、时间、状态、关联和附件元数据（名称/MIME/大小/哈希）。接收方为自己的 Personal OS 应用服务，再按当前本人会话读取 Supabase；不发送给 AI，不发送图片/音频文件，不写入档案或保存提交内容。不提供选择部分对象导入，以免破坏关联闭包。

服务端先检查同源、本人身份、已启用契约，再以流式有界读取 JSON（8 MiB 元数据＋1 KiB 封装上限），独立校验版本/字段/计数/引用，不相信客户端校验结论。单进程一次预检、超时/取消与服务失败均返回错误；响应 no-store，异常不含私人原文或数据库详情。原有 service-role/匿名/公开 Storage 均不新增使用。

快照不包含未绑定上传。因此按候选附件 ID 分批（100 个）只读查询本人未绑定附件的 id；发现同编号占用则标为不支持，不偷偷绑定或覆盖。未绑定检查晚于逻辑快照，不能宣称整套结果对以后提交持续有效。没有公开遍历 Storage，没有下载目标原件做字节复验。

## 3. 对比规则

- 按对象表和 ID 区分记录、条目与原件；条目 kind 变化仍是同 ID 冲突。
- 原文空白、说明、标签/链接/来源/附件数组顺序、字段、原始创建时间和回收站时间均参与对比；原件比较名字/MIME/大小/SHA-256/归属，附件差异也使所属记录标为冲突。
- 对象键顺序不影响；等价时区写法按同一时点比较，保留亚毫秒精度；UUID 大小写正规化并重新检测重复。sourceVersion 仅是来源并发信息，不用它判断逻辑内容差异；不修改实际版本。
- 缺失对象列“待新增”，完整相同列“相同，拟跳过”，同 ID 逻辑有差异列“冲突”；这些都是预览，不代表任何操作已执行。
- 来源自引用/环、方向关联环、回收站 Focus、关联已移除方向、新对象引用目标库回收站来源、同编号未绑定附件列“不支持”。任一冲突或不支持都会显示“整批应停止”。原件缺失、格式/引用破损则本地或服务端拒绝，不能产生可用结果。
- 云端不在包内的额外对象只显示数量，保持原样；不返回这些对象的私人标题/原文。结果只含候选 ID、类别、判断与差异字段名；列表标题来自本地包。

结果只表示某次读取的元数据对比，不是恢复授权、云端原件健康证明或可恢复证明。将来写入仍需重新检查权限、当前数据/版本、真实原件及幂等，不能直接信任此结果或客户端传入的批次状态。没有写入接口/按钮、恢复任务表、原件暂存或清理。

## 4. 页面与异常

设置 → 校验本机备份（或生成并校验新包） → 读发送说明/展开材料 → 勾选同意 → 只读对比云端 → 按新增/相同/冲突/不支持查看。列表每次显示 20 项，可继续展开；清除条件回“全部”。显示对比时点、回收站与停用关注标记、目标额外项数。

取消、超时、会话过期、数据库读取失败均不写入；取消/换文件后迟到响应不能重新显示旧结果。失败保留已校验本地材料，可主动重试。撤销勾选会清除结果，清除预检不删除本地校验；没有自动重试或自动处理下一步。窄屏按卡片换行，键盘可操作与查看文字，触摸控件沿用至少 44px。
