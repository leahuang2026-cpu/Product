## 2. 三个概念与本轮推荐范围

- **同步**：设备看到同一份现状；误操作可能同步，不能代替备份。
- **应用完整备份**：用户手动下载独立文件，包含已保存内容、原始附件、关系和回收站状态；包通过校验及隔离恢复演练后，才有相应恢复证据。
- **平台灾备**：数据库、Auth、Storage、配置等基础设施的重建。另行核验服务能力；应用 ZIP 不能直接重建账号、密钥和整套 Supabase。

建议首批做用户主动发起的完整备份与本地校验，再做恢复预检，最后单独进入真实恢复写入。首版不增加自动定时备份、第三方云盘、通知、公开下载、永久清理、AI、全库替换或旧浏览器档案迁移。

## 3. 可迁移的文件合同（建议）

采用普通 ZIP 容器，JSON 是权威数据；原件独立文件，不以 base64 全塞入 JSON：

```text
personal-os-backup-<UTC 时间>-<备份 ID>.zip
  manifest.json
  records.json
  entries.json
  attachments.json
  originals/<附件 UUID>.<允许的扩展名>
  README.txt
```

- manifest：format=personal-os-backup、formatVersion、备份 UUID、数据契约版本、UTC 快照时间、生成完成时间、实际内容范围、对象/状态计数、每个 JSON/原件的相对路径/字节数/SHA-256。列出需保护的文件，不包含 manifest 自身的循环哈希。
- records / entries / attachments：按 2.1 的白名单字段组织，保留关联与时间精度。附件文件名由 UUID/MIME 推导，用户原始文件名只作元数据，不作为解压路径。
- README：格式说明、未加密状态、离线阅读方式、范围排除和支持的恢复版本。JSON 中的链接只当文本，恢复时不执行 HTML/SQL/脚本或访问包内外任意 URL。
- 校验既检查每个条目的哈希，也检查目录无缺件、多件或重复路径、计数一致。SHA-256 用于完整性，不是来源签名，也不提供保密性。
- 不将签名链接、bucket 名或来源服务器路径作为可恢复内容。换目标项目时，由服务端依据当前本人身份重新构造原件路径；身份认证和权限基础要先单独就绪。

建议首版为**未加密 ZIP，用户手动下载到自己设备**，界面明确包含私密原文与回收站内容。若要求口令加密，应提前调整格式与实现范围，使用成熟认证加密方案；不能把 ZIP 格式或 SHA-256 称为加密。口令、密钥及真实备份均不进入 Git/开发日志。

## 4. 导出技术与页面流程

设置新增“云端档案备份”，与“旧版浏览器档案”和“回收站内恢复”分开。展示完整范围及不加密说明 → 用户确认导出 → 生成快照并读取原件 → 浏览器下载 → 用户可再选文件作只读完整性校验。

### 4.1 一致性与权限

1. 复用服务端本人会话、已安装数据契约、同源写请求校验；不需要 service-role 作为常规导出权限，不把 publishable key 当作本人授权。
2. 评审新增 **security invoker 的只读快照 RPC**，在同一数据库快照读取原始表白名单字段、计数与已绑定附件，包含 deleted_at。不能用两次普通列表/多页独立请求冒充同一时点快照。大数据分页若无固定快照方案则不能宣称一致。
3. Storage 原件与数据库不能使用同一事务；利用现有不可覆盖约束，对快照中的每个原件验证字节数和 SHA-256。缺失、下载失败、哈希错误都使完整包生成失败；不把剩余部分称为完整备份。
4. 导出后的新记录/编辑不倒灌本次快照。界面说明快照时间，用户下载备份不会自动改变 Focus/Direction 或清空回收站。
5. 为回收站原件读取建立导出内部路径，不解除普通原件入口的 410、Owner RLS 或 bucket 私有性。所有响应 no-store，不放 CDN/公开 bucket；不写正文、文件内容和令牌到日志。

### 4.2 传输与资源边界

推荐服务端逐文件流式生成 ZIP；不使用整包 base64，不依赖 Render 容器本地磁盘持久保存备份。浏览器原生下载/流式落盘与不支持该能力的手机浏览器回退，必须在 BKP-01 用合成数据验证后确定具体实现。

若需要准备任务再下载，任务标识必须绑定本人会话，不是公开 bearer 下载凭据；持久状态不能仅存在进程内或临时磁盘。首版不默认增加第三方对象存储或新付费服务。

**待技术预研后确认的上线门槛**：实际 Render 实例资源、超时、并发数、最大元数据量/总原件字节数、ZIP 总包限制及 Safari 下载行为。现有单文件 10 MB 仍保留，不将其扩大成“任意大小整包可备份”。若超出已验证范围，应拒绝并解释，不截断、不偷偷只导出第一页；需要分卷或持久导出任务时另列范围。

成功反馈分开：“已开始下载”“服务端传输完成”“所选本地包校验通过”“隔离恢复演练通过”。浏览器下载请求成功不证明文件已可靠存入设备或一定可恢复。

## 5. 备份校验与安全预检

先提供浏览器本地只读校验：检查格式版本、路径、解压上限、JSON schema、文件哈希/计数和引用完整性，列出正常/回收站/Focus/方向/复盘/附件数，不上传或写云端。分离“结构/哈希有效”与“目标空间可恢复”。

恢复上传前只读分析目标库，形成新增、完全相同跳过、冲突、不支持/缺件等计数与清单。预检可以在限定大小内把必要元数据提交本人服务端；不把完整原件或档案送给 AI/其他服务。

必须防止：Zip Slip、绝对路径、反斜杠/规范化路径重复、符号链接、ZIP 炸弹、压缩/解压后超限、重复 UUID、伪造 MIME、哈希错误、缺附件、来源或方向悬空、可执行内容及未知格式。校验包里的 SHA-256 不是信任包的授权；最终仍校验本人身份、字段及全部约束。

## 6. 恢复合同（建议，真实写入后续单独实施）

### 6.1 默认不覆盖规则（待 Owner 确认）

- **相同 ID 且完整逻辑内容相同**：跳过。原文、元数据、时间、链接、附件顺序和哈希、引用及回收站状态均参与比较；不能仅凭 ID 或原文相同跳过。
- **相同 ID 但任一内容/状态不同**：整批停止并显示冲突；不自动覆盖、改原文、换 ID 复制或把回收站记录恢复成正常状态。若用户后续需要“作为副本导入”，另评审并全量重映射关系。
- **不存在的对象**：在 Owner 看过预检并明确确认后补入；保留原始时间、关系、active/cadence/回收站标记。新行运行时 version 重新初始化，sourceVersion 只作备份信息，不改既有行版本。
- 不含在包内的目标库条目保持原样；不提供“清空后恢复”“强制全量替换”或跨账号权限迁移。目标空间必须已经完成本人认证/表/权限基础安装，不从包内创建 Auth 用户或执行 SQL。
- 同一包、同一恢复批次失败重试/重复确认不重复创建。成功结果以持久批次结果和实际读回为准，不能仅用界面 disabled 阻止重复。

### 6.2 不可直接复用普通保存 API 的原因

当前原文、created_at、附件归属有不可变触发器；逐条调用保存会得到新时间、版本冲突和部分成功。现有回收站触发器还阻止新引用已移除来源。不能为恢复临时关闭触发器/RLS、用 service-role 绕过或先恢复既有回收站数据。

建议后续评审 **受本人 RLS 限制的专用批次恢复 RPC** 和最小持久恢复任务记录（Owner、批次 ID、包/预检哈希、状态、已接收原件、结果计数；私有，不写入开发日志）。结构和权限必须作为单独增量提案，不在本轮写 SQL。

### 6.3 跨数据库与 Storage 的失败边界

1. 全包校验 + 目标只读预检，有冲突/缺件/不支持关系则不进入写入。
2. 用户确认后按任务清单接收必要原件。沿用服务端 owner/附件 UUID 路径与 upsert=false；已存在对象须验证真实字节相同，否则停止，不能覆盖。
3. 原件校验齐全后，单个数据库事务内再次核对目标，插入所有缺失对象并重建关系；失败则逻辑记录事务全部回滚。按记录来源依赖排序、先方向后 Focus，并在事务内部处理待恢复的回收站状态；这些内部中间状态不对外可见，不修改已有行。
4. 成功提交及批次结果同事务持久化；若响应丢失，通过同批次结果核对，不再执行第二次插入。事务内二次核对处理预检之后的并发变更。
5. 文件已接收但数据库未提交时，可能留下未绑定私有对象。它们不是已恢复档案，不出现在普通列表；明确显示“未恢复完成，可续传/重试”。当前没有删除原件权限，不自动清理这些对象、不承诺 Storage 回滚。后续清理需单独规则和授权。
6. 取消预检不写入；接收原件中取消可保留私有暂存及进度；提交中取消/断网不代表事务取消，必须先查批次结果，不能据此删除已写内容。

**首版恢复的保守限制**：来源环/自引用、无法满足现有数据库约束的包，应在预检时解释并整批停止。若新增记录引用目标库中已经在回收站、因此会被插入触发器拒绝的来源，也先停止，不自动移动原件或绕过保护。这些限制不影响完整导出；空档案的全量隔离恢复仍必须演练。

“新行补入 + 相同跳过”不是把现有空间回滚到旧快照；若当前同 ID 内容已变化，会阻止旧包恢复。整库灾难恢复要在单独准备好的空目标空间演练，不在日常空间清空测试。

| BKP-06         | 真实合成包演练及 Owner 验收；依赖 BKP-05                      | 隔离恢复环境/测试记录/操作说明                                  | BKP-A15：导出→本地校验→空目标恢复→读回原件/关联/状态；原空间不受影响                        | 空目标/测试账户由 Owner 准备；不自动创建付费项目     |

推荐批准后先做 BKP-01～03（完整导出 + 校验），再依据实测和预检结果进入 BKP-04～06；不在第一个交付里上线未演练的恢复写入。自动化备份、加密及跨版本升级后置不等于永久排除。
