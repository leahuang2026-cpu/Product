## 3. 首批最小页面流程（拟定设计）

下列流程使用 PRD 已确认的安静保存原则；“跳过/未分类”、编辑细则和 Focus 关系仍需 Owner 确认。

### 手机录入与图片

`首页快速入口 / Capture → 输入文字或选择图片（可附说明）→ 保存 → 成功反馈 → 分类选项 → 详情或继续记录`

- 保存原文/原图成功后才显示成功；分类是第二次独立操作，失败不回滚已保存原件。
- 建议分类可跳过，后续从详情修改；不预选“自我”，不自动调用 AI。
- 空白提交提示；网络、读取或上传失败保留本次界面输入/选择并允许重试。刷新或系统杀掉浏览器后的离线草稿恢复不默认纳入。
- 图片先取得上传凭证，上传原件，再确认记录就绪；最后确认失败可重试同一请求，不能产生重复档案。缩略图不替代原图。
- 先评审单张 JPEG/PNG；大小上限、多图、WebP/HEIC 和拍照入口需确认。验证软键盘、相册权限取消、弱网、后台切换与真实手机文件。

### 档案

`Archive → 关键词/分类查找 → 详情 → 查看原文或原图 → 补说明/改分类 → 保存 → 重新打开核对`

列表与详情均从本人授权数据读取。区分加载中、无匹配、读取失败和会话过期。基础查询建议先支持正文与图片说明关键词，不包含 OCR、语义搜索或自动推荐。原文全文编辑、版本历史和删除待 O03，不能以“编辑说明”隐含批准覆盖原文。

### 首页与当前关注

`设置当前重点 → 关联方向或项目 → 填一条下一步 → 保存 → 手机/电脑首页显示三项信息`

用户主动编辑下一步、移出当前关注；移出仅影响展示关系，不删除档案、方向或项目。首次没有 Focus 时给设置入口，不自动把前两个项目当重点。建议一个关注至多选一个关联对象；是否必选、可同时显示几条和排序规则待确认。这里的“一条下一步”指每个关注项的文本，不等于只允许一个 Focus。

## 4. 数据与权限技术方案

推荐沿用 Next.js + TypeScript，候选云端使用 **Supabase PostgreSQL + Auth + 私有 Storage**。Vercel 作为后续部署候选。理由是复用现有应用，并减少单人项目分别维护数据库、账户和文件服务的工作；代价是区域可达性、供应商依赖、流量/存储/备份费用与权限配置成本。独立 PostgreSQL + S3 + Auth 控制更强但运维更多；本地 SQLite/localStorage 本身无法满足已确认的云同步。

最小模型按功能启用，而非一次实现全部历史对象：

| 阶段         | 候选对象                                     | 关键约束                                                                                                                                      |
| ------------ | -------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| 文字/图片    | Record、Attachment、认证用户标识             | Record 保留原文/时间；分类、说明独立元数据。Attachment 存私有对象键、所属记录、媒体类型、字节数、上传状态，可留校验和；不把 Base64 存入业务行 |
| 当前关注     | Focus、Direction/Goal、Project               | Focus 保存标题、一条下一步、展示状态和明确关联；方向与 Goal 不另造重复概念；项目仅启用最小名称/关联，不引入完整任务系统                       |
| 后续单独批准 | 记录灵感标记、Review 与来源关联、AI 派生结果 | 原件不被 AI 覆盖；不预建向量库、Agent、全历史自动处理或复杂灵感生命周期                                                                       |

- 每个业务对象含 `owner_id`。服务端验证会话和本人允许的账户；数据库 RLS 约束用户归属；关联对象也必须同属一人，防止伪造外键越权。
- 建议使用用户 JWT 的 Supabase 数据接口及必要的 SQL 事务函数，SQL migration 为唯一云数据库变更来源。普通 Prisma 高权限直连不自动执行用户级 RLS；既有 schema 暂作历史设计，不与 SQL 双轨迁移。最终技术选型待确认。
- 图片使用私有 bucket；上传授权只准对应用户/记录的对象键并验证格式与大小。**A10 要求已知图片地址也不能被未授权会话读取**，推荐 Next.js 鉴权内容入口、私有且 `no-store` 的响应；短期签名下载 URL 是可转发的凭证，不能独自满足该要求。生产代理流量成本后续核实。
- DB 与对象存储没有跨服务事务：用上传待完成/就绪状态、请求幂等键及受控补偿来处理“上传成功但数据库确认失败”。不得自动清除用户原件；孤立上传的回收期限待评审。
- 云端提交成功后才标记已保存/已同步；另一端刷新获取最新值。更新带版本条件并显式处理冲突，不静默覆盖。离线写入队列、后台实时同步和多端自动合并不是当前默认范围。
- 数据库备份与对象备份分别设计；现有 JSON 导出不等于云备份。导出范围、保留期、恢复目标在真实资料长期使用前评审；本轮不迁移或读取私人数据。

更完整的候选比较见 [T01 架构](architecture-v0.1.md)、[模型](data-model-v0.1.md)与[可行性](technical-feasibility.md)。本报告不改变其“待确认”状态。未重新核实供应商现行套餐与区域价格，不承诺免费额度，不创建任何资源。
