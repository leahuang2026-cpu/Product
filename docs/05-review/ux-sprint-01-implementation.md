## 数据提案与启用门槛

[private-records-v2.sql](../02-engineering/proposals/private-records-v2.sql)是可审查的新表/RPC/权限提案，**未应用到 Supabase**。它不迁移或删除旧表，使用独立名称和 Owner UUID 白名单；记录原件有不可变触发器，附件禁止覆盖，更新有版本检查和请求去重。

提案已在独立内存 PostgreSQL（PGlite）验证；Auth/Storage 的 schema 是测试替身，不代表 Supabase 实际服务已测试。实际部署前仍需核查默认授权、Storage 现有策略、Email provider、认证回调、账号 UUID、备份与资源预算。不得只设置 `PERSONAL_OS_DATA_CONTRACT=reviewed-v2` 就称为安全可用。

未采用 service-role 处理用户 CRUD。原图由服务端本人会话读取，响应 private/no-store，不重定向到 bearer 签名下载地址。数据库备份与原图备份/恢复未完成，不能把云同步当作备份。

## 实际验证

- ESLint、TypeScript、生产构建通过（最终复核见 DEV-007）。
- 领域/边界测试：13 通过，保留旧格式往返测试，新增多选、混合输入、原件字段拒绝与来源边界。
- 内存 PostgreSQL：7 个场景与父测试共 8 通过；验证保存幂等、元数据重放、不可变原件、多领域、标记取消、附件绑定、账户隔离、存储路径及匿名拒绝。
- 浏览器：1440/390/320/768 四宽度，48 场景通过。交互测试明确模拟 API；另有对真实本地端点的匿名与跨来源拒绝测试。
- 既有 Prisma WASM：13 个模型校验通过；该模型没有迁移或替代本轮 SQL 提案。
- Supabase 只读连接检查：环境代理返回 `Tunnel connection failed: 403 Forbidden`；未进行真实登录、发送邮件、云端写入或权限修改。

首次浏览器验证发现隐藏文件 input 被通用宽度规则覆盖，引起横向溢出和移动端点击坐标偏移，已修复。测试 PNG 不能通过真实解码，已用 sharp 生成有效合成图替换；Next 路由 announcer 与测试 alert、搜索按钮与搜索输入的定位冲突均已修正。内存 SQL 验证发现函数参数/列名歧义，已限定参数并重测通过。

这些结果不等于 A01–A18 的真实云端产品验收。真机麦克风权限、录音编码、邮件登录、云端存储与跨设备必须后续实测。
