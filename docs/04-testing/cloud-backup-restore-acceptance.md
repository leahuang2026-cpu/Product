## 2. 合成数据集要求

数据集应有：保留前后空白/换行的文字、多领域/未分类、仅图片记录、HTTP(S) 链接、同记录灵感标记、带 sourceId 的手写补充、方向与 active/inactive Focus、带与不带来源的周/月复盘、含原件/来源的回收站条目。使用固定合成内容、独立账号/库和测试 bucket，不读取或把真实私人备份放入测试工程。

单独生成恶意/损坏包覆盖路径、压缩、字段、权限与状态边界；不可把真实用户包修改后提交 Git。实际持久性、Storage 行为和事务并发必须有 PostgreSQL/Supabase 与存储联验，PGlite 和 API fixtures 不能替代全部结论。

## 3. 分层执行与证据

1. 格式/比较器单元：哈希、字段保持、路径、冲突和上限；必须包含反例，不能只测实现的内部步骤。
2. 隔离 SQL：新快照/任务/恢复 RPC 的 Owner 隔离、版本/幂等、原子性和原件保护；不对日常数据库迁移或清库测试。
3. 浏览器合成接口：页面状态、取消、清除文件选择、错误恢复、四宽度与键盘；结果注明 fixtures。
4. 实际服务联验：下载包原件、手机文件处理、会话过期/第二身份、任务重启、原件暂存与 DB 提交；逐项记录已测/失败/未测。
5. 隔离恢复演练：先准备已安装基础权限的空目标；准备/费用需实际核查，不自动新建付费资源。导出方与恢复方分别对账，不用 HTTP 200、平台 Live 或包生成代替 A15。

每次执行记录日期、代码/数据契约/包格式版本、命令退出码或手动步骤、用例数、设备、通过/失败/未测和缺陷；日志只放脱敏摘要。下载完成、校验通过及恢复演练是独立状态。

## 4. 上线前停止条件

格式/总量限制未经明确、任一权限/原文保护/冲突/重复写入反例失败、完整性校验可绕过、存在静默漏导出、逻辑部分恢复却显示成功，均阻止相应功能上线。没有 BKP-A15 的恢复演练证据，不把导出功能称为“已验证可恢复的完整备份系统”。
